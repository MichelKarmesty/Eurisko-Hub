# ADR 008: Self-Service "Forgot Password" Restored, Backed by the Built-In Mail Transports

> **Amended by [ADR-009](ADR-009.md).** The self-service route and its transports
> described here are **retained but off by default**: recovery is Admin-initiated
> (`POST /users/:id/reset-password`, ADR-007) and `POST /auth/forgot-password`
> answers `404` unless `PASSWORD_RESET_SELF_SERVICE=true`. Everything below stays
> as the record of how the emailed path works when an operator enables it.

## Problem Statement

ADR-007 removed the self-service recovery path (`POST /auth/forgot-password`)
along with the entire mail subsystem, on the grounds that it required a mail
provider the rest of the product does not depend on. Recovery became
Admin-initiated: an Admin mints a one-time link and hands it over.

In practice that turned out to be the wrong default for the people using the
hub. It forces every "I forgot my password" onto a colleague (or onto the
offline `scripts/reset-password.mjs`), even in deployments that **do** have a
mail server or are happy to configure one. The removed machinery — a
dependency-free SMTP client, a webhook relay, a Resend call and a console
fallback — already existed and was tested; deleting it saved nothing at runtime,
it only removed a capability. The request: bring self-service recovery back and
have it send a real reset link to the account's email address.

## Decision Options

### Option 1: Keep Admin-initiated only — not selected
Retains ADR-007 exactly, but keeps every reset dependent on a human Admin or the
offline script, despite mail being available.

### Option 2: Restore self-service and drop the Admin path — not selected
Reverses ADR-007 wholesale. Simpler, but it throws away a working no-mail
fallback: a deployment without a provider (or a failed one) would be left with
only the offline script.

### Option 3: Restore self-service, keep the Admin path as the fallback — selected ✓
`POST /auth/forgot-password` comes back, mails the one-time link through the
restored `MailService`, and coexists with everything ADR-007 added: the
Admin-issued link (`POST /users/:id/reset-password`) and the offline
break-glass. Both paths mint the same single-use, hashed, time-limited token and
complete through the same `POST /auth/reset-password`.

## Selected Decision

**Self-service recovery is restored as the primary path, and the ADR-007 paths
stay as fallbacks.** `POST /auth/forgot-password`:

* always answers the same generic message — the address registered or not,
  active or not — so it cannot enumerate accounts;
* mails the link through the restored `MailService`, which never throws and
  degrades transport by transport: primary SMTP (`SMTP_HOST`…) → **backup SMTP**
  (`SMTP_ALT_HOST`…, so a deployment can run Gmail *and* Outlook and survive one
  of them being down) → `MAIL_WEBHOOK_URL` → `RESEND_API_KEY` → console. Each
  SMTP sender has its own `*_FROM` because Gmail rewrites a mismatched sender to
  the authenticated account and some servers reject it outright;
* returns the one-time token in the response **only outside production**
  (`PASSWORD_RESET_RETURN_TOKEN`, always suppressed when
  `NODE_ENV=production`), so the flow stays demonstrable with no mail server;
* throttles re-sends per address (`PASSWORD_RESET_COOLDOWN_SECONDS`, default
  60 s, in-memory) so it cannot be used to mail-bomb a victim.

The Admin-issued endpoint, the offline script, the token storage (SHA-256 hash +
expiry), single-use semantics, and the "a change clears any outstanding token"
rule are all unchanged — the two routes share one code path
(`AuthService` token machinery + `UsersService` reset columns).

## Consequences & Rationale

**Benefits**
* Users get their password back without involving a second person wherever mail
  is configured, while deployments with no provider still work exactly as
  ADR-007 described (console print + dev token).
* No schema change, no new dependency: the SMTP client is hand-rolled
  (`backend/src/mail/smtp.client.ts`), exactly as before its removal.
* The security properties of the token itself (hash-only storage, expiry,
  single-use) carry over untouched because both paths share the same machinery.

**Trade-offs**
* A public endpoint now sends email, so it needs abuse protection the
  Admin-only path never did: the per-address cooldown is a modest in-memory
  throttle, not a full rate limiter — a deployment facing the open internet
  should still put the API behind its usual gateway/rate-limiting.
* The dev convenience (`PASSWORD_RESET_RETURN_TOKEN`) puts a live token in an
  HTTP response outside production; it is **always** off when
  `NODE_ENV=production`, and explicitly switchable to `false` anywhere.

**Mitigation**
* Non-enumerating: identical generic answer for every input, pinned by tests.
* Cooldown per address; no email is sent for unknown/inactive accounts at all.
* A misconfigured provider falls through to the console rather than failing the
  request — availability is preserved, and in production the `Mail` logger
  warns loudly that email is not actually leaving the process.

## Implementation Impact

* `backend/src/mail/` restored — `MailService` (primary SMTP → backup SMTP →
  webhook → Resend → console), `smtp.client.ts`, `mail.module.ts`;
  `backend/test/mail-smtp.spec.ts` restored and extended with the two-sender
  fallback (`smtp-alt`).
* `backend/src/auth/` — `forgotPassword()` restored in `AuthService` (with the
  per-address cooldown and `exposeResetToken`), `ForgotPasswordDto` restored,
  `POST /auth/forgot-password` route restored; `AuthModule` imports `MailModule`.
* `backend/.env.example` — the SMTP block, the optional `SMTP_ALT_*` backup
  sender, `PASSWORD_RESET_RETURN_TOKEN` and `PASSWORD_RESET_COOLDOWN_SECONDS`
  restored.
* `scripts/setup-mail.mjs` and `scripts/verify-mail.mjs` restored and extended:
  the wizard accepts **two** addresses (it recognises Gmail/Outlook from the
  domain and asks for the host otherwise), and the check tests **every**
  configured sender, passing when at least one delivers.
* `frontend/` — `AuthScreen.tsx` regains the **Forgot password?** mode (the
  console delivery carries the link straight into the reset form in dev),
  `api.ts` regains `apiForgotPassword` and knows the `smtp-alt` delivery label.
* Tests — `backend/test/auth-password.spec.ts` covers the generic non-enumerating
  answer, the dev token + `delivery`, production suppression, the cooldown, and
  the full emailed-link flow; `backend/test/mail-smtp.spec.ts` covers the real
  SMTP conversation and the primary-fails → backup-delivers path; the ADR-007
  suites are unchanged.
* Docs — this ADR, the ADR-007 amendment banner, [api.md](../api.md),
  [security.md](../security.md), the root and backend READMEs.
